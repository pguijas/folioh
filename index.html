v0.1Shipped

Foundation

Source analysis

Python first: source in, documented site out.

  • One command sets the project up
  • Reads your source, never runs it
  • API reference and your guides in one site
  • Types in signatures link to their pages
  • Edit a docstring, see the page
  • A component library and full-text search
  • llms.txt from day one
v0.2Shipped

Theming

Visual ownership

Own the look at any depth, then ship it anywhere static files go.

  • Presets, shareable packages, or your own template
  • Readers retheme the site from the site
  • A preview site per pull request
  • Social preview images
v0.3Shipped

One Binary

One platform

One native binary reads Python, JavaScript and Rust; the built-in plugins share one contract, and this site runs on it.

  • The core in Rust: one native binary, no Python to install
  • Three readers in the binary: Python, JavaScript, and Rust
  • Built-in plugins ship pages, components, and data
  • Your own React components in any page
  • Every project ships its authoring contract
  • Every page gets a portable Markdown mirror
  • Roadmap, landing, and OpenAPI integrations
v0.4Up next

Agent Ready

Agent surfaces

A documentation harness for your coding agent: it writes the docs, keeps them in step with the code, and migrates them from any documentation tool. Every piece is built around Folioh, from the skill to the MCP server.

  • Agent discovery by the specs: .well-known and text/markdown negotiation
  • folioh mcp — search and read the docs from your editor, read-only
  • Every project ships a skill that teaches agents to write and maintain its docs
  • The site serves that skill to agents that never cloned the repo
  • A typed export of the whole site for tools and agents
  • Per-page structured data and content signals for search engines and AI crawlers
  • Your agent moves documentation from any tool to Folioh with a migration skill and a few scripts
  • Every theme polished across documentation, components, and mobile
v0.5Later

Every Language

Reach

One site for every reader: the language the code is in, the version they are on, and the language they read. New languages arrive as parsers, not new toolchains.

  • TypeScript, then Go, C#, and Java, next to Python, JavaScript, and Rust
  • Versioning — docs for every version of your library
  • Internationalization — sites in your readers' languages
  • Cross-language references
  • One search, one llms.txt, every language
  • Inline type information in examples
  • Folioh's own API reference, read by its Rust reader
  • Python read in depth: inherited members and re-exports
v1.0Later

Open Platform

Extensibility

Others extend it and get seen: project plugins return, a language is something you can add, the projects built on Folioh get a home, and 1.0 draws the stability lines.

  • Project plugins return as sidecars over JSON-RPC
  • Language contract — a public way to add a language
  • Other tools add their own commands to the folioh CLI
  • Built with Folioh — a catalog of the projects and plugins built on Folioh, open to outsiders
  • One site across products and repos
  • The OpenAPI plugin becomes a full reference: a page per endpoint, schema fields, requests you can try, and Swagger 2.0 specs
  • Starter templates
  • Live plugin demos with their source
